# Локальная "база" — как перенести на сервер

Сейчас все данные (курсы, промокоды, вес, история тренировок, заказы,
бонусы, сегменты колеса) живут в `localStorage` браузера/WebView, по
одной копии на устройство. Это сознательный временный слой — весь
остальной код обращается к нему через `Repo<T>` (`list/get/add/update/
remove/replaceAll`), то есть **так же, как обращался бы к REST/RPC API**.

## Когда появится сервер

1. В `localStore.ts` заменить реализацию `createRepo` на HTTP-клиент
   (`fetch('/api/<table>')` с теми же методами и сигнатурами) — это
   единственный файл, который нужно переписать.
2. Ни один экран, ни админка менять не придётся — они вызывают
   `coursesRepo.list()`, `ordersRepo.add()` и т.д., а не localStorage
   напрямую.
3. Что дополнительно понадобится на сервере и чего сейчас нет:
   - Авторизация пользователя (сейчас — просто Telegram `initData`,
     без проверки на бэкенде).
   - Пароль админки (`src/admin/AdminLoginPage.tsx`, сейчас захардкожен
     в клиентском коде — временное решение, замените на реальную
     сессию/JWT на сервере, иначе пароль виден любому в devtools).
   - Реальные платежи (сейчас "Купить курс" — имитация, ничего не
     списывается) — see `CoursesPage.tsx` / `CourseCard.tsx`.
   - Синхронизация между устройствами — сейчас каждый телефон видит
     только свои локальные данные.

## Таблицы

| Repo                 | Что хранит                              |
|-----------------------|------------------------------------------|
| `coursesRepo`          | каталог курсов (редактируется в админке) |
| `promoCodesRepo`        | промокоды                                |
| `weightRepo`            | история веса пользователя                |
| `workoutLogRepo`         | история завершённых тренировок           |
| `ordersRepo`             | заказы/покупки курсов                    |
| `bonusLedgerRepo`         | начисления/списания бонусных баллов      |
| `wheelSegmentsRepo`       | сегменты колеса фортуны                  |
